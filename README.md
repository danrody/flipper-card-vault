# Card Vault для Flipper Zero

Зашифрованное хранилище на SD-карте Flipper Zero. Открыть его можно только при двух условиях: введён **пароль** и к Флипперу приложена **карта Mifare Classic**. Открытое хранилище подключается к ПК как обычная USB-флешка. Расшифровка идёт «на лету», поэтому на SD никогда не попадает открытый текст.

<sub>English summary: encrypted XTS-AES-256 USB drive for Flipper Zero, unlocked by password + Mifare Classic 1K card, with an offline recovery key and a PC companion tool.</sub>

## Возможности

- **XTS-AES-256** (IEEE 1619, как в VeraCrypt/LUKS/BitLocker) для данных, на аппаратном AES-движке STM32WB.
- Два фактора: пароль + **752 случайных байта** на карте (все 47 блоков данных Mifare 1K), 32 уникальных случайных ключа секторов.
- **5 неверных паролей → хранилище уничтожается** (заголовок затирается, образ удаляется).
- **Резервный ключ** (`recovery.key`) — открывает хранилище без карты и пароля, позволяет назначить новый пароль и новую карту, расшифровать данные вообще без Флиппера.
- Автоблокировка при отключении USB-кабеля и при «извлечении» диска на ПК.
- Самопроверка криптографии (known-answer tests) при каждом запуске: если аппаратный AES ведёт себя не по стандарту — приложение отказывается работать.
- Конвейерный ввод-вывод (SD ↔ шифрование ↔ USB параллельно), анимации.

## Криптография

```
пароль ──PBKDF2-HMAC-SHA-512 (соль 256 бит, итерации ≈2.5 с на Флиппере)──► P (512 бит)
P ──HKDF-SHA-512──► проверочное значение (на SD, для счётчика попыток)
P ──HKDF-SHA-512──► 32 ключа секторов карты (A/B × 16)
P ‖ секрет карты (752 байта) ──HKDF-SHA-512──► KEK (256 бит)
KEK ──AES-256-GCM──► обёрнутый мастер-ключ (512 бит = XTS ключ данных + ключ твика)
мастер-ключ ──XTS-AES-256──► сектора vault.img
```

Все контексты HKDF привязаны к случайному ID хранилища. Секреты затираются в памяти сразу после использования. Мастер-ключ генерируется аппаратным TRNG.

## Модель угроз — честно

| Ситуация | Результат |
|---|---|
| Украли только Флиппер / SD-карту | данные защищены (нужен секрет с карты, 6016 бит) |
| Украли только карту | данные защищены (нужен vault.img и пароль) |
| Украли Флиппер **и** карту | Mifare Classic (Crypto-1) взламывается за минуты; остаётся только пароль → используйте длинный пароль, храните карту отдельно |
| Копия SD снята заранее | счётчик попыток живёт на SD и откатывается копированием; пароль подбирается офлайн — но без карты бесполезен |

Также: клавиатура Флиппера показывает пароль на экране при вводе; затирание файлов на SD не гарантировано из-за wear-levelling флеш-памяти (поэтому `recovery.key` нельзя хранить на SD).

## Установка

Нужна прошивка Unleashed (проверено на `unlshd-093`, API 88.9) и [uFBT](https://github.com/flipperdevices/flipperzero-ufbt):

```bash
python3 -m venv .venv && .venv/bin/pip install ufbt cryptography pyserial
.venv/bin/ufbt update --index-url=https://up.unleashedflip.com/directory.json --channel=release
cd card_vault && ../.venv/bin/ufbt launch     # сборка + установка в Apps/Tools
```

## Использование на Флиппере

**Create vault** → размер (до 4 ГБ) → пароль ×2 → приложить **чистую** карту Mifare Classic 1K → скачать резервный ключ на ПК (`cardvault.py fetch-key`) → **Erase** (копия на SD уничтожается).

**Unlock** → пароль → приложить карту → на ПК появляется диск `CARDVAULT`. Заблокировать: извлечь диск на ПК, выдернуть кабель или «Назад → Lock».

**Check card** — проверка карты: все 47 блоков, уникальность, баланс бит, 32 ключа, отказ заводского ключа. Сам секрет не показывается.

## PC-утилита `tools/cardvault.py`

Положите `recovery.key` рядом со скриптом (или укажите `--key`).

| Команда | Что делает |
|---|---|
| `fetch-key` | скачать резервный ключ сразу после создания хранилища |
| `unlock` | открыть хранилище как USB-диск **без карты и пароля** |
| `rekey` | новый пароль + новая чистая карта (старая перестаёт работать) |
| `decrypt --image vault.img --out plain.img` | расшифровать без Флиппера (SD в кардридере) |
| `encrypt --plain plain.img --out vault.img` | зашифровать обратно |
| `verify --image vault.img` | проверить, что ключ подходит |

`recovery.key` = полный доступ к данным. Храните офлайн (флешка в сейфе, бумага).

## Тесты

```bash
.venv/bin/python tests/run_host_tests.py
```

C-код криптографии и FAT32 собирается нативно (ASan/UBSan) и сверяется с `hashlib`/`cryptography` (OpenSSL): SHA-512, HMAC, PBKDF2, HKDF, XTS; созданный образ проверяется `fsck.fat`, расшифровывается/шифруется утилитой.

